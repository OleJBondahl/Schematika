Bundling all 7 in one wave + threshold drop + multiple migration docs busts the **≤ 600 LoC / ≤ 30 files** per-wave cap.

C2d is therefore split into 4 sub-waves:
- **C2d-1** (this wave) — `add_reference`, `add_equipment` (2 tier-1 add_* methods).
- C2d-2 — `CircuitBuilder.build` (1 tier-1 method, complex, separate due to risk).
- C2d-3 — `build_from_descriptors`, `create_horizontal_layout`, `_walk_loop`, `_register_connection_pair` (4 internal/tier-2/tier-3 helpers).
- C2d-4 — drop `max-args = 16 → 8` in `pyproject.toml` + clean `SUPPRESSIONS.md`.

## Wave scope

Hard breaking change for both methods. Two migration docs.

### Bundle additions to `core/options.py`

**Two new dataclasses**. The 6 existing dataclasses (PlacementOptions, TerminalDisplayOptions, ConnectionOptions, TerminalConfig, SymbolConfig, SpdtConfig) are UNCHANGED.

```python
@dataclass(frozen=True, slots=True, kw_only=True)
class EquipmentConfig:
    """PID equipment factory + tag prefix + factory passthrough."""

    factory: "SymbolFactory"  # PID's SymbolFactory protocol
    tag_prefix: str
    factory_kwargs: Mapping[str, Any] | None = None


@dataclass(frozen=True, slots=True, kw_only=True)
class EquipmentPlacement:
    """PID equipment placement: anchor-relative (relative_to + ports + offset) OR absolute (position OR x,y)."""

    relative_to: str | None = None
    from_port: str = "outlet"
    to_port: str = "inlet"
    offset: tuple[float, float] = (0.0, 0.0)
    position: "Point | None" = None
    x: float = 0.0
    y: float = 0.0
```

- Both are frozen/slots/kw_only. Single-line tier-3 docstrings.
- `SymbolFactory` and `Point` imported under `if TYPE_CHECKING:` (PID-side types). The PID `SymbolFactory` is `schematika.pid.symbols.SymbolFactory` — distinct from electrical's `schematika.electrical.model.core.SymbolFactory`. The TYPE_CHECKING import resolves correctly at type-check time without any runtime cost.
- **Note**: `add_reference` does NOT need a new bundle — it reuses `PlacementOptions` and `ConnectionOptions` from C2a. **`**factory_kwargs` is kept** as a separate `**kwargs` param on `add_reference` because the post-bundle count is already 4 (well below 8) and bundling a single field of `**kwargs` would add ceremony with no benefit. (Distinct decision from C2a-c which removed `**kwargs` to hit ≤5/≤4 targets — here we're aiming for ≤8 and have headroom.)

### `add_equipment` body changes

Same pattern, but with PID-specific bundles:

```python
def add_equipment(
    self,
    name: str,
    /,
    *,
    config: EquipmentConfig,
    placement: EquipmentPlacement | None = None,
) -> PIDBuilder:
    """<tier-1 docstring>"""
    plc = placement or EquipmentPlacement()

    if name in self._entries or name in self._instruments:
        msg = f"Equipment '{name}' already registered"
        raise PIDValidationError(msg)

    spec = EquipmentSpec(
        factory=config.factory,
        tag_prefix=config.tag_prefix,
        name=name,
        kwargs=dict(config.factory_kwargs) if config.factory_kwargs else {},
    )

    if plc.relative_to is not None:
        if plc.relative_to not in self._entries:
            msg = (
                f"Cannot place '{name}' relative to '{plc.relative_to}': "
                f"'{plc.relative_to}' has not been registered yet"
            )
            raise PIDValidationError(msg)
        from_anchor = Placement(
            anchor=plc.relative_to,
            anchor_port=plc.from_port,
            my_port=plc.to_port,
            offset=Vector(*plc.offset),
        )
        entry = _EquipmentEntry(spec=spec, placement=from_anchor, abs_position=None)
    else:
        abs_pos = plc.position if plc.position is not None else Point(plc.x, plc.y)
        entry = _EquipmentEntry(spec=spec, placement=None, abs_position=abs_pos)

    self._entries[name] = entry
    self._equipment_order.append(name)
    return self
```
